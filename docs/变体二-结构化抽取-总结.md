# 变体（二）结构化抽取：实现与整年运行总结

> 课题：证据引导的长期决策记忆（YC-Bench）
> 状态：功能已实现，记忆臂已跑满一年（种子 42，Gemini 3 Flash Preview）；基线臂整年数据待跑。

---

## 一、变体定义

课题提案中的变体（二）要求**不做任何改写**，只把智能体自己产生的观测结构化地记录下来，再以紧凑形式回灌上下文。三条硬性约束写在代码里，不是口头约定：

1. **只用智能体自己能观测到的信息**。事件来源仅限它自己命令的标准输出与仿真唤醒事件，不读取模拟器的隐藏属性（例如客户忠诚度、内定标记、未来结果）。
2. **只增不改**。事件写入后永不修订、永不删除；把观测合并成更正的记录属于变体（三），不属于本变体。
3. **每条事件附带证据**，可回溯到具体命令、轮次、仿真时刻，因此任何一行渲染进提示词的内容都能反查来源。

对应实现位于 `src/yc_bench/memory/`，5 个模块共 1400 行。

| 文件 | 行数 | 职责 |
|---|---|---|
| `schema.py` | 177 | 事件词表、任务键规则、证据构造、写入前校验 |
| `store.py` | 78 | 只增不改的 JSONL 持久化，附内存镜像 |
| `extractor.py` | 506 | 从命令流抽取事件；接单后自动补一次只读查询 |
| `view.py` | 409 | 把事件流折叠成任务记录，再聚合成客户统计并渲染 |
| `pipeline.py` | 180 | 对外门面：每轮观测入口与视图输出 |

## 二、机制

### 2.1 事件词表

| 事件类型 | 触发观测 | 关键字段 |
|---|---|---|
| 接单 | 执行接单命令，配合此前浏览时的挂牌量 | 接单时刻、截止日、挂牌需求量、挂牌报酬 |
| 核查 | 执行任务核查命令 | 实测需求量、任务状态 |
| 派工 | 执行派工命令 | 派出的员工列表 |
| 完成 | 仿真推进的唤醒事件 | 是否成功、提前或逾期时长、现金变动、信任变动 |
| 取消 | 执行取消命令 | 取消原因 |

任务标识用「标题@接单时刻」。任务标题会在后续市场生成中被复用，接单时刻才是智能体可观测的唯一判别键。

### 2.2 双源测量：本变体的核心

挂牌量和实际需求量来自两个不同来源，缺一不可：

- **挂牌量**来自市场浏览的输出，智能体看过；
- **实际需求量**只能从任务核查拿到，而任务被接受后工作量才固定。

问题在于智能体本身几乎不主动核查。为此配置项 `followup_reads` 置为真，让记忆模块在每次接单之后**自己发一条只读查询**（`extractor.py` 第 334 行返回核查命令），用的是智能体本来就有权执行的同一条命令，不额外授予观测权限。

于是「实测与挂牌之比」才可计算。这层信息在单次浏览中完全不可见，只能靠历史累积。

### 2.3 视图是事件流的纯函数

视图生成函数每轮都重新执行「事件流折叠」，不维护任何跨轮状态。因此：

- 视图内容严格由事件流决定，不存在「记忆被悄悄改写」的可能；
- 同一份记忆日志重放必然得到同一份视图（已用全部 840 条事件复算验证）。

渲染进提示词的部分控制在 300 个词元以内，形如：

```
### 客户记忆（依据你自己的历史命令自动记录）
  接单量/挂牌量 = 实际接受的工作量 ÷ 挂牌列出的数量（1.0 表示与挂牌一致）
Stratos Cloud: 62 接 | 62 成 0 败 0 取消 0 在途 | 接单量 0.6 倍 (62/62) | 最近 12-31 提前 171 小时
Vanguard ML:    3 接 |  0 成 3 败 0 取消 0 在途 | 接单量 4.0 倍 (3/3)  | 最近 09-30 逾期 97 小时
```

## 七、三个发现

### 7.1 机制闭环成立：记录、注入、影响行为

从半年前的 20 轮调试到这次整年运行，同一条链路反复出现并稳定复现：

1. 接单后自动核查，事件落盘，视图随即出现「接单量 4.0 倍」；
2. 智能体在草稿本中写下规避结论（大意是「高倍率客户应当避开」）；
3. 后续派工与接单随之改变。

这次整年的直接体现是把 204 单压到四家 0.6 至 0.7 倍的客户上。这需要跨数十轮的累积统计，单轮上下文做不到。

### 7.2 结构化抽取恢复的信息是真实的，但判断没跟上

Vanguard 与 Equinox 的记录从头到尾都准确：零成功、全部失败、4.0 倍。但这两家全年仍被接了 6 单，**5 次失败全部落在它们身上**，其余四家客户 204 单零失败。

失败时间分布在 1 月 16 日、1 月 21 日、4 月 14 日、6 月 4 日、9 月 16 日，典型的「失败后消停两三个月再试一次」。

最典型的一例在最后一天：从 50 个报价中挑了两单，报酬几乎相同（$6,892 与 $6,889），但 Equinox 那单需要 3916 单位工作量，Helix 只需 750，相差五倍。记忆里那条「Equinox 零成两败、4.0 倍」就在上下文中，仍然接了。当时市场有 200 个未接任务、六家客户都有单，不存在「别无选择」。

结论是**信息可得性已经解决，从先验到行动的转化没有解决**。这不是抽取质量问题，而是视图只陈述过去结果、缺乏可执行判断的张力度问题：两次失败样本在 62 次成功的对照下显得不显著。

### 7.3 全程零次取消

210 单里一次取消都没有。5 次失败全部走「接下、硬扛、超期」的路径。取消只扣声望不动现金，而失败要倒扣 35% 现金，止损的机制手段存在但从未被使用。

## 八、局限

1. **基线臂整年数据缺失**。目前只有记忆臂整年结果，无法把「记忆带来的增量」从「模型自身能力」中剥离。这是当前最大的缺口，补齐之前结论只能写成观察，不能写成因果。
2. **单种子**。种子只决定仿真世界，不传给模型（运行时仅设温度 1.0），每次运行都是独立抽样。单次资金比较包含抽样噪声，需要多种子才能给出区间。
3. **上下文成本偏高**。143 次市场浏览均未限制条数，按默认 50 条返回全量数据，提示词长期稳定在 90k 词元左右。这一点两臂一致，不影响可比性；若做下一轮实验，把默认条数降到 10 可将单轮成本压到约三分之一。
4. **员工视图未启用**。配置中该项为关闭，渲染函数已实现但未注入。这是有意关闭的变量，两臂一致。
